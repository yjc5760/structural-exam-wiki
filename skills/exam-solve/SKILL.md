# exam-solve — 考古題解題流程（五科通用）

把一份考卷的每一題解成深度解析檔 `XX/raw/solutions/XX-YYYY-N/XX-YYYY-N.md`。
`XX` 是科目代碼（SS／RC／SA／SD／SM），所有路徑都在 `XX/` 底下。

本 skill 只管**流程**。下列內容以知識庫內的正本為準，不要憑記憶，也不要在這裡另存一份：

| 要什麼 | 讀哪裡 |
|--------|--------|
| 不可違反的規則（`raw/` 唯讀、verified 不可質疑） | 根目錄 `CLAUDE.md`「重要規則」 |
| 命名、LaTeX 規範、VHA 表格模板、JSON 欄位 | 根目錄 `CLAUDE-SPEC.md` §1.2、§1.4、§2.1、§3.3、§3.4 |
| 子項表、designMethod 允許值、互動圖內容碼、**設計哲學框架** | `XX/SUBJECT.md` §2、§3、§4、§8 |
| 考卷檔名 | `XX/SUBJECT.md` §1 |

---

## 0. 開始前

1. 確認科目。使用者沒說科目、對話也看不出來時，先問「哪一科？」，不要猜。
2. 讀 `CLAUDE.md`、`CLAUDE-SPEC.md`、`XX/SUBJECT.md`。
3. 確認考卷 `XX/raw/exams/XX-YYYY_<科目名>.pdf` 存在；不存在就請使用者放入，停止。
4. 讀 `XX/raw/json/question_index.json`，找出該年尚無解析（`hasSolution` 不為 true）的題目。已有解析的題目**跳過**，不覆蓋。

---

## 階段一：建資料夾、列截圖清單（收到「解析 YYYY 年 XX 考卷」後）

1. 讀考卷。⚠️ 考卷常是 Adobe-CNS1 CID 字型，`pdftotext` 抽不到中文；公式表、附表也常是影像。
   **一律把每頁轉成 300 dpi 圖片後目視閱讀**（支承符號、尺寸線、銲接符號太小時用 450–500 dpi）。
2. 為每道尚無解析的題目建立資料夾 `XX/raw/solutions/XX-YYYY-N/`。
3. 逐題判斷有無附圖：
   - 有附圖 → 列出存檔路徑 `XX/raw/solutions/XX-YYYY-N/XX-YYYY-N-fig-1.png`（多張依序 `-fig-2` …）
   - 無附圖 → 標「無需截圖」（仍要建資料夾）
4. 輸出截圖清單，附上截圖品質要求後**停止**，等使用者說「截圖完成，請開始解題」：
   - 完整包含結構示意圖、幾何標示、載重符號；不含其他題目文字；上下留白
   - 相鄰的多張子圖截成一張；分散的分開存 `-fig-1`、`-fig-2`

---

## 階段二：逐題解析（收到「截圖完成，請開始解題」後）

**一次只解一題**：解完、存檔、更新索引後停止，等使用者說「繼續下一題」。（避免單次輸出超過上限。）

每題的步驟：

1. 先讀考卷**最後一頁的參考公式**與附表 —— 考卷給的公式優先於設計哲學框架與記憶。
2. 讀該題的 fig PNG（看不到圖就不要解，請使用者補圖）。
3. 做**三層掃描**（下節），再依 `XX/SUBJECT.md` §8 的設計哲學框架決定路徑。
4. 依「解析輸出格式」寫 `.md`，存到 `XX/raw/solutions/XX-YYYY-N/XX-YYYY-N.md`。
5. 計算型題目：**每個數值都用程式算一次**，不要心算或手打；最終答案與程式結果一致才存檔。
6. 符合 `XX/SUBJECT.md` §4 的題型時，產生互動圖 `XX-YYYY-N-<內容碼>-viz.html`，並在 §4 開頭加連結。
7. 更新 `question_index.json`（見「索引更新」）。
8. 跑「完成檢核」，回報結果後停止。

### 三層掃描（解題前先做）

先見林（外在全貌）→ 再見樹（策略路徑）→ 後見土（內在意圖）

```
第一層 外在：[目標] 最後要交出什麼（數字？圖？OK/N.G.？）
             [已知] 題目給的數字與條件（斷面、材料、載重、幾何、參考公式）
             [待算] 從已知到目標需要的中間參數
第二層 策略：[邏輯] 對照 XX/SUBJECT.md §8 的哪一條框架
             [陷阱] 考官可能挖坑的地方（非標準型式、模糊用字、易混觀念）
             [捷徑] 哪些條件可以跳過步驟
第三層 內在：[核心] 本題最重要的一個觀念
             [線索] 特殊用字的暗示（例：「無面外束制」→ 側扭挫屈；「忽略自重」→ 善意簡化）
```

### 解析輸出格式（每份 `XX-YYYY-N.md`）

```
# 考題編號：[XX-YYYY-N]

**主分類：** `XX-Un-m` 子項名稱
**副分類：** `XX-Un-m` 子項名稱（可含他科子項；無則省略）
**設計法：** （XX/SUBJECT.md §3 的允許值）
**標籤：** `標籤1` `標籤2` `標籤3` …

---

## 1. 原始題目重述
   - 重述題幹與子題；以文字描述附圖所有關鍵資訊
   - 圖片引用（alt text＋「*圖說：*」，讓看不到圖的人也能解題）
   - 參考公式截圖 eqn-n.png 的圖說要把公式完整寫成 LaTeX
## 2. 考題核心精神與出題者意圖
## 3. 解題戰略地圖與陷阱分析（步驟化作戰計畫＋3–4 個關鍵陷阱）
## 3.5 變數層次分析（VHA）← 必須輸出，格式照 CLAUDE-SPEC.md §3.4
   - 最終目標（一句話）
   - 本題關鍵公式 5–8 步，只寫符號不代數字；前步已算出的中間變數用 \boxed{} 框起
   - L1 題目直接給定｜L2 需知識點推導｜L3 深層知識；L2、L3 的「卡關?」欄一律留空
## 4. 步驟化詳細計算過程
   - 完整公式、單位、中間結果；關鍵步驟附「策略註解」；最終答案用 \boxed{}
## 5. 關鍵爭議點與進階探討（多種解讀時的最安全作法、規範版本差異）
```

附圖引用格式：

```markdown
![XX-YYYY-N 題目附圖：[精確描述結構型式、幾何、載重]](XX-YYYY-N-fig-1.png)

*圖說：[關鍵幾何數值、支承條件、載重位置、斷面尺寸等完整文字說明]*
```

### 索引更新（`question_index.json`）

解完一題就更新該題條目（沒有條目就新增）：

| 欄位 | 由本 skill 填 | 說明 |
|------|:---:|------|
| `hasSolution` | ✅ | true |
| `primaryTopicId` | ✅ | 本科子項 |
| `secondaryTopicIds` | ✅ | 陣列；他科子項只能放這裡 |
| `designMethod` | ✅ | 只能用 `XX/SUBJECT.md` §3 的允許值 |
| `tags` | ✅ | 至少 3 個具體考點 |
| `verificationStatus` | ❌ | 新題一律 `unverified`；只有使用者驗算後明說，才改成 `verified` |
| `hasHandwritten` | ❌ | 使用者放入 hand PNG 後才改 |

### 完成檢核（每題存檔後逐項確認，回報給使用者）

- [ ] 檔名、路徑為 `XX/raw/solutions/XX-YYYY-N/XX-YYYY-N.md`，H1 含題號
- [ ] §3.5 VHA 存在；`\boxed{}` 標出中間變數；卡關欄全部留空
- [ ] 正文沒有純文字公式符號（`Mu`、`Fcr` 要寫成 `$M_u$`、`$F_{cr}$`）
- [ ] 所有數值有程式重算紀錄；單位一致
- [ ] 圖片都有 alt text＋圖說；互動圖檔名有內容碼與 `-viz` 後綴
- [ ] `question_index.json` 已更新，`designMethod` 在允許值內，`tags` ≥ 3

---

## 解完之後（提醒使用者）

```
1. 確認 fig PNG 品質；需要時補 chart／eqn／hand 截圖（XX-YYYY-N-chart-1.png 等）
2. 人工驗算 → 說「將 XX-YYYY-N 的 verificationStatus 改為 verified」
3. 說「ingest XX-YYYY-N」→ 寫入該科 wiki
4. 說「繼續下一題」→ 解下一道尚無解析的題目
5. 全年解完後說「更新 XX 儀表板資料」
```

## 不要做的事

- 不要一次解多題、不要覆蓋已有解析（要改既有解析請用 exam-errata）
- 不要修改 `raw/exams/` 與使用者截圖
- 不要自行把題目標成 `verified`
- 設計哲學框架與考卷公式衝突時，以考卷為準，並在 §5 說明
