# 題目正本拆分（exam-problem-split）

把每題的「考卷寫了什麼」從解析裡拆出來，存成凍結的題目正本 `raw/solutions/<id>/<id>-problem.md`。判讀確認後，有附圖的題目依判讀清單重繪附圖（與 exam-solve 階段一第 6 步相同），解析 §1 改為指向題目正本並放重繪圖。目的：題意先單獨驗證，讀錯題的錯誤在動解答前就被抓到；重繪圖上每個支承、尺寸、載重都對應判讀清單一項，讓判讀結果看得見。

新題目的解題流程用 exam-solve（`Downloads\[考古題知識庫]\skill\exam-solve.skill`，階段一的讀題法與本 skill 相同）。本 skill 處理**已有解析的題目**的補建。

在題庫總流程（exam-wiki-pipeline）中本 skill 是階段 A：先定題意，再由 exam-wiki-audit 盲解比對。本 skill 第 4 步會打開解析 §1，**同一對話接著盲解就不算獨立**；盲解要在另一個對話做，或在比對報告揭露。

## 0. 開工前（每個 repo 第一次做時）

1. 讀 repo 的 `CLAUDE.md` 與 `wiki/queries/log.md` 最後幾筆，確認沒有其他工作階段正在改同一批檔。
2. 考卷 PDF 在各科 repo 的 `raw/exams/`（例 `C:\Users\yjc57\Downloads\exam-wiki-RC\raw\exams`）。只有 SS 的考卷進了 git；其他科只在使用者本機，GitHub 上沒有，**一律從本機讀**。請使用者把該科 repo 資料夾連進來；`raw/exams/` 找不到檔案就停下來問。
3. 找題目瀏覽頁的渲染腳本：SS、SD 是 `scripts/render_problem_view.py`，SA 是 `scripts/md2view.py`（自 2026-11-04 起已支援「📄 題目正本」區塊），RC 是 `scripts/gen_problems_view.py`，SM、MM 沒有。尚未支援的腳本：偵測到 `-problem.md` 時，在解析前插入「📄 題目正本」區塊（照 SS 的 `render_problem_view.py` 或 SA 的 `md2view.py` 做）；改完對沒有題目正本的題目重產，確認輸出 0 差異。沒有腳本的科目，先和使用者確認要新建腳本還是只建 problem.md。
4. `CLAUDE.md` 規則 1 的「raw/ 不可修改」例外加入 `<id>-problem.md`（照 SS、SA 的寫法：建立時待確認、確認後凍結、凍結後要改須回考卷原圖並記 log）。資料流與資料夾結構也補上 problem.md 與重繪圖 `figs/<id>-fig-N-problem.svg`，CHANGELOG 加一列。
5. `raw/json/question_index.json` 的 `tagSystem` 加 `problemStatus` 說明（draft／confirmed；欄位不存在 = 尚未建立）。順便檢查 `tagSystem` 有無亂碼（SA 曾有 UTF-8 被當 cp1252 再編碼一次的字串）。

## 1. 分批

- 以單元（主分類）為單位，依年份排序，每批 6–10 題（結構學剛架題圖單純時可到 12 題）。計算題多、圖多的單元（接合、構架）批小一點。
- 副分類題留給它主分類所屬的單元。
- 開始前用 `question_index.json` 列出該單元還沒有 `problemStatus` 的題目。
- 若已有盲解稽核產生的題目正本草稿（`wiki/queries/題目正本草稿-XX/`），以它為起點改寫成本 skill 格式，仍要回考卷原圖核對。

## 2. 盲讀（先讀考卷，不看解析）

1. 取得考卷影像（考卷只在本機時）：
   - 優先用 `device_stage_files` 把該批考卷 PDF 送到雲端工作區，在雲端用 PyMuPDF 轉圖後直接看。
   - 若無法 stage：在本機 shell 用 `pdftoppm`（本機通常沒有 PyMuPDF）轉 PNG 存到 repo 外的暫存處，再 stage PNG。
   - SS 的考卷在 git 內，也可用 GitHub 上同一 commit 的副本轉圖，但要先比對與本機的 md5。
2. 每份考卷 110 dpi 全頁轉圖，逐頁看。可抽文字的考卷用 pdftotext 核對逐字原文。
3. 附圖用 300–500 dpi 局部放大。定位用 PDF 文字座標或內嵌圖片的 bbox，不要用猜的座標。
4. 向量圖（曲線圖、尺寸線）可讀 PDF drawings 座標取值或核對端點；這些座標之後也是重繪的依據，記在判讀清單的依據欄。
5. 題內公式若是圖片，用 `pdftoppm -r 150 -x -y -W -H` 截成 `<id>-eqn-N.png` 放在題目資料夾（在本機 shell 直接對 `raw/exams/` 的 PDF 執行）。
6. 證據圖：沿用解析既有的 `<id>-fig-N.png`。先做一張全批證據圖的縮圖總表，一次看出哪幾張有問題。既有圖裁切不完整、解析度太低（小符號看不清）、**截圖帶有滑鼠游標等雜訊（尤其壓在支承或尺寸上）**、或該題有附圖卻沒有 fig 檔時，從考卷重新擷取 500 dpi PNG（repo 有 `scripts/extract_figure.py` 就用它，否則用 PyMuPDF 依 bbox 裁切），存成下一個未用的編號，不覆蓋既有證據圖。

**歷次查到的讀錯題型態，盲讀時逐一檢查：**
- 尺寸線端點量到哪裡：全深 vs 腹板淨高、外緣 vs 中心線、外緣 vs 形心。
- 支承符號：鉸、滾、固定、導槽；A／B 端是否標反。題文「某點為鉸接」是鉸支承還是構架內鉸，看圖上該點有沒有鉸圈。
- 銲接符號：雙面／單面、全周銲圓圈、長度與間距（L-150）、現場銲旗、哪一面沒有符號。
- 螺栓：行列數、哪一片板、單剪／雙剪、邊距量到哪裡。
- 載重：作用點、方向、斜率、作用範圍（全跨或部分跨）。
- 附圖沒標尺寸、只能從圖面量測的幾何（例：支承是否在另一點正上方）：把握標「確定（解讀）」，會影響答案時請使用者確認。
- 題目沒給、卻被解析寫成題目事實的條件（載重組合、φ、Fr、自重、承壓型、斷面形狀、EA）。
- 題文用詞與符號不一致（「設計」配 Mn、「標稱」配 φ）。
- 考卷公式筆誤（照錄並註明，卷首通常要求考生自行修正）。

## 3. 寫題目正本 `<id>-problem.md`

只寫考卷有什麼，**不寫解法**。固定結構：

```
# <id> 題目正本
> 本檔只記錄考卷上寫了什麼、圖上畫了什麼，不含任何解法。解析見同資料夾 `<id>.md`。
> 判讀清單經使用者確認前，狀態為「待確認」；確認後本檔原則上不再修改（改動須回考卷原圖並記 log）。

| 項目 | 內容 |  ← 考卷（檔名、頁、題號）、考年、配分、附圖（檔名）、判讀狀態：**待確認**（轉錄日期、dpi、盲讀後才比對）

## 1. 考卷原文（逐字）   ← 照抄，含錯字（另註「照考卷原文」）
## 2. 考卷給的公式、附表與參數   ← 照錄；明寫「沒有給」哪些東西；卷首注意事項
## 3. 附圖   ← 用證據圖 fig-N.png；alt 描述圖上畫了什麼；「圖面文字照錄」
## 4. 判讀清單   ← | # | 項目 | 判讀 | 圖上／題文依據 | 把握 |
---
*轉錄：日期（<單元> 題目正本推廣・批 N）*
```

判讀清單規則：
- 「把握」只用三種：確定／確定（解讀）／不確定（解讀）。
- 會改變答案的不確定項，把握欄寫「不確定（影響答案，請確認）」。
- 依據要具體：dpi、尺寸線端點對齊哪條線、PDF 座標值。
- 有附圖的題目，清單要涵蓋重繪需要的每個元素（構件、支承、節點、每條尺寸線與量測基準、每個載重），之後重繪圖上不得出現清單沒有的東西。
- 考卷沒給、但容易被補全的條件，在清單加一列「考卷沒有給」明寫出來。

題目正本 §3 只放證據圖，**不放重繪圖**（題目正本記錄考卷，重繪是判讀結果，放解析 §1）。

同步：`question_index.json` 該題加 `"problemStatus": "draft"`（插在 `verificationStatus` 之後，用正則插入，保留原格式，最後 `json.loads` 驗證）。

## 4. 比對解析 §1

盲讀完才打開解析。逐題判定：✅ 一致／⚠️ 加字或漏讀（答案不受影響）／❌ 讀題錯誤（影響答案）。影響答案的要用程式重算新舊兩種讀法的數值，寫進報告。題意以外的解析錯誤另列一節。

⚠️ 加字（解析重述多了考卷沒有的條件）時，全文搜尋該條件，列出 §1 以外也建立在它上面的段落（§2 出題意圖、§3 陷阱、§5 探討…），確認後第 7 節一併刪除。

另外記下每題解析既有的自繪圖（`figs/*.svg`、`gen_<id>.py`）裡有沒有已經畫出題目幾何的圖，以及它和判讀清單是否一致；不一致的列入報告（重繪時會以判讀清單為準）。

**本輪不改解析 .md。**

## 5. 產出與檢查

1. 重生該批題目瀏覽頁。
2. KaTeX 檢查：用 repo 的 `study/assets/katex` 對 `<main>` 內每個數學式 renderToString（throwOnError），錯誤須為 0；去掉數學式與 `<code>` 後殘留的 `$` 須為 0。殘留 `$` 若來自解析既有內容，列入報告。
3. 分類稽核（`scripts/audit_classification.py` 或 exam-wiki-audit 的同名腳本）0 問題。
4. 報告 `wiki/queries/題目正本-<單元>-批N-<日期>.md`：範圍、讀法、§1 比對表、影響答案的項目（含重算數值與下游引用）、題意以外的問題、既有自繪圖與判讀不一致處、確認後要重繪的題目清單、待確認清單、確認後步驟。
5. `wiki/queries/log.md` 加一筆 `PROBLEM-SPLIT-<單元>-B<N>`。
6. 改動前把該批解析與索引備份到工作區外（例 `~/bkN/`），log 註明位置。

## 6. 回報使用者

- 先講結論：幾題一致、有沒有讀錯題、幾題確認後要重繪。
- 影響答案的項目逐一說明證據與數值變化，請使用者**明確選擇**（有 AskUserQuestion 時用它，一次問完）；其他不確定項列成清單。
- 使用者只回「繼續」「確認」時，視為不確定項照本檔判讀定案；但影響答案的項目要再問一次。
- 列出動到的檔案路徑，**git commit 交給使用者**。未 commit 變動很多時提醒先 commit。

## 7. 確認之後（每批一支腳本 `scripts/fixes/<日期>_confirm_sec1_<單元>_B<N>.py`）

腳本要可重複執行（已處理過的題目略過），每一步 assert；先在雲端可取得的題目副本上試跑，再到使用者 repo 執行。

1. problem.md：「待確認」→「已確認」（頭表寫確認日期，影響答案的項目寫明使用者的選擇；不確定項把握欄加「；使用者確認」，問句類寫明定案的處理），頁尾加「確認：日期 使用者確認」。索引 draft → confirmed。
2. 影響答案的項目依 repo 的解析勘誤規則（exam-errata；回考卷原圖、程式重算、同步下游、頁尾修正日期、log 用 `FIX-` 標題）勘誤解析，並同步單元總覽、講義等引用處。
3. **重繪附圖**（有附圖的題目；載入 `struct-diagram` skill 依其規範產圖）：
   - 依已確認的判讀清單畫 `figs/<id>-fig-N-problem.svg`＋2× PNG。每個支承、尺寸、載重都必須對應清單上的一項；幾何由清單數值與座標決定，不憑印象。節點標籤、支承符號位置盡量照考卷附圖。
   - 繪圖程式：題目資料夾已有 `gen_<id>.py`（解析自繪圖用）時，在同一支檔案加一個 problem 圖函式與對應輸出，不改既有圖的程式與輸出（重跑時輸出到暫存目錄，只寫回新的 `-problem` 檔）；沒有就新建 `gen_<id>.py`，程式庫照 repo 慣例放 `figs/_lib/`。
   - 另產生「原圖｜重繪」並排對照圖（存 repo 外暫存處，不進 `.md`、不進 git），每題看一次確認一致，回報時附給使用者抽查。常見問題：尺寸標籤被畫布邊界切掉、尺寸線壓到圖說、節點標籤壓在支承剖線上、`√` 等符號在數學字型缺字（改用一般文字標註）。
   - **不重繪**：設計圖表、曲線圖（重繪等於自己編數據）、圖本身就是表格者、本題無附圖者。
   - 解析既有自繪圖已經畫出題目幾何、且與判讀清單一致時，仍另畫 `-problem.svg`（重繪圖只畫考卷給的東西，不含任何解題結果）；不一致的既有圖在報告中列出，交使用者決定是否勘誤。
4. 解析 §1 改為：

```
## 1. 題目（考卷原文見題目正本）

> 考卷原文、公式／附表、附圖與判讀清單（已確認）見 [`<id>-problem.md`](<id>-problem.md)。本節只列解題時最容易讀錯的地方與本解使用的記號；題意以題目正本為準。

![<id> 重繪題目附圖：精確描述](figs/<id>-fig-1-problem.svg)
*重繪自考卷附圖，依題目正本判讀清單；圖說寫本圖攔下的判讀錯誤（例：尺寸量至腹板淨高而非全深）。*

### 常見誤讀
| 項目 | 正確判讀 | 常見誤讀 |

**本解記號：** …
```

   - 無附圖或不重繪的題目，省略重繪圖那兩行。
   - 刪除前 assert：舊 §1 引用的每個 png 都已在 problem.md。
   - 舊 §1 內解析自繪的向量圖（`figs/*.svg`，非 `-problem.svg`）不能刪，移到 §1「判讀圖解（解析自繪）」小節。
   - 舊 §1 若有勘誤時加的「常見誤讀／本解記號」文字，整理進新的常見誤讀表與本解記號，不可丟失。
   - 第 4 步列出的「建立在虛構條件上的段落」一併刪除（assert 找得到），刪完再全文搜尋該條件一次，確認只剩常見誤讀表與頁尾。
   - 正文其他地方引用「§1 圖說」的，改指題目正本判讀編號。
   - **頁尾修正日期的寫法**（exam-wiki-audit 的 pending.py 依此判斷是否已勘誤，寫錯會讓這題被跳過盲解）：
     - 本步驟的修改一律寫成 `*修正日期：YYYY-MM-DD（§1 改為指向題目正本…）*`，括號內**必須以「§1 改為指向題目正本」開頭**，後面可接重繪圖檔名、刪除虛構條件段落、修正數學式格式等非勘誤修改。
     - 同批若也補了解題圖解，可寫進同一行（「；§5 補解題圖解 figs/…」）。
     - 影響答案的勘誤（第 2 步）**另寫一行**，照 exam-errata 格式，不要合併到上述那行。
     - 頁尾說明是純文字，**不要寫出字面的錢號符號**（會被當成數學式，KaTeX 檢查會出現殘留）；要提到就寫「單錢號／雙錢號」。
5. 重生瀏覽頁、KaTeX 檢查、圖片引用存在性檢查、稽核、log 加 `PROBLEM-SPLIT-CONFIRM-<單元>-B<N>`（註明重繪了哪幾題）。

## 8. 補重繪（已確認、但當時沒有重繪的題目）

本 skill 加入重繪步驟前已確認的題目（例 SS 的 U1-1、U2-1 及 U1-2 部分題），使用者說「補重繪」時：

1. 用 `question_index.json` 列出 `problemStatus` = `confirmed`、有附圖、但 `figs/` 沒有 `-problem.svg` 的題目，依單元分批（每批 6–10 題）。
2. 每題只讀已確認的題目正本與證據圖重繪（判讀已凍結，不重新盲讀）；重繪時發現判讀清單缺項或與證據圖不符，**停下來**列入報告，不自行補判讀、不改 problem.md（要改走題意勘誤）。
3. 依第 7 節第 3 步產圖，把重繪圖插入解析 §1（引用區塊之後、常見誤讀之前），頁尾加 `*修正日期：YYYY-MM-DD（非勘誤）補重繪附圖 figs/<id>-fig-N-problem.svg*`（必須含「（非勘誤）」，理由同第 7 節）。
4. 重生瀏覽頁、KaTeX 檢查，log 加 `PROBLEM-REDRAW-<單元>-B<N>`，報告附並排對照圖，列出動到的檔案路徑，git commit 交給使用者。

## 注意

- 多個工作階段可能同時改同一 repo：寫入前看目標檔 mtime 與 log 末段。
