## 1. 講稿寫法

- **一段 = 一個想法**，10–25 秒（約 45–110 字）。段落太長，畫面會停在同一版太久；太短，換板太頻繁。
- 範例 SM-2020-3：22 段、6 章（題目 → 方法一 → 陷阱 → 方法二驗算 → 第三種驗算 → 總結），配音後 6 分 22 秒。估計（每秒 4.6 字）通常比實際配音短 15–20%。
- **每個陷阱都講「錯在哪 + 錯了會得到什麼數字」**：例如「如果寫成乘，孔隙只剩 13.5 毫升，比水還少，一看就不合理」。錯誤結果本身就是檢核工具，這是這類影片最有價值的地方。
- **數字寫國字**：五百、零點二七、百分之七十、一點零三二九。TTS 念阿拉伯數字常念錯小數或念成英文。
- **符號寫念法**：V s、e max、伽瑪 d。避免希臘字母原字元（γ）。字幕端用 `SUB_SYMBOLS` 轉回。
- 停頓用 `<short pause>`，放在揭曉答案前、轉折前。
- 總結段用「第一、第二…」條列，最後一句重述答案。
- 講稿確認前先跑 `python make_srt.py --preview`，看有沒有「一樣 → 1樣」這種誤轉，補進 `SUB_KEEP`。

## 2. Manim 版面與動畫

**座標**：畫面 x ∈ [-7.1, 7.1]、y ∈ [-4, 4]。左上角 y ≈ 3.4 被標題列佔用；y < -3.3 盡量留空（萬一要燒字幕）。

**版面慣例**（範例實際用法）：
- 圖（柱狀圖、三相圖）放一側，計算式放另一側；換章時 `clear_board()`。
- 同一個量全片同一色：分子粉紅、分母藍、答案黃框、錯誤紅字＋`xmark()` 打叉、正確綠勾。畫面上的色塊要和算式的顏色對應（例如分子的柱段也畫粉紅雙箭頭）。
- 重要的圖可以跨段保留，縮小移到角落（`.animate.scale(0.58).to_corner(UR)`）；後面章節要回顧時用 `.copy()` 做迷你版。

**寫完動畫一定要看畫格**：`manim -ql` 渲染後跑 `python frames_grid.py`，用 Read 看 `frames_grid_*.png`。第一次渲染幾乎一定有文字重疊或超出右緣（範例第一版有 6 處），常見原因：
- 算式寫太寬：一行 MathTex 在 font_size 42 時，每個符號約 0.3 單位寬，含分數的一行常超過 6 單位。降到 38–40，或拆成兩行。
- 兩欄靠太近：左欄算式的右緣要和右側圖的標籤錯開。
- 前一段的標籤沒清掉，被新的虛線穿過：該段結束前 `FadeOut`。

**MathTex 取字（上色、劃掉某個符號）**：glyph 索引不直觀，先用除錯圖確認：
```python
self.add(m, index_labels(m[0], label_height=0.12, color=RED))   # manim -s 出單張圖看編號
```
分數的順序是「分子 → 分數線 → 分母」；巢狀分數同理。例：`D_r=\frac{\dfrac{V_{max}-V}{V_s}}{\dfrac{V_{max}-V_{min}}{V_s}}` 裡兩個 V_s 是 [10:12]、[23:25]。

**其他**：
- MathTex 裡不能放中文（LaTeX Unicode 錯誤）。中文用 `T()`，再用 `row()` 併排。
- `Text` 的子物件不含空白：「500 ml 之砂土」要取「500 ml」，索引要用去掉空白後的字串計算。
- 動畫總長若超過該段配音，`end()` 不會截斷，只是那段後面多出靜音。重渲染後檢查 timeline.json 每段長度是否 ≤ 配音 + 0.6 s（見 SKILL.md 步驟 5）。
- `-qh` 是 1080p60，6 分鐘片約需 10 分鐘渲染；審閱用 `-qm`（720p30）約 3 分鐘。

## 3. 配音（TTS）

- 預設 Gemini TTS（`gemini-3.8-flash-tts`），聲音 Charon（資訊型男聲）。其他適合講解的男聲：Sadaltager（博學）、Iapetus（清晰）、Rasalgethi（資訊型）、Orus（堅定）。
- `python tts_gemini.py --audition A,B,C` 用第一段試聽；`--list-voices` 找台灣口音聲音；也可以在 Google AI Studio 用文字描述設計聲音，得到 `voice_...` ID。
- 語氣用 `GEMINI_STYLE` 描述；口音不自然時可加 `Taiwanese Mandarin accent`。
- 某段念錯：改 segments.py 那段文字（例如改寫法讓它念對）→ `run_tts.bat --only s07` → 重跑步驟 5。
- Azure 備用（`zh-TW-YunJheNeural`）：`tts_azure.py`，`<short pause>` 會轉成 SSML break。

## 4. 字幕對齊（make_srt.py）

第一版「按顯示字數比例分配時間」的做法，字幕最多搶快 2 秒，觀眾明顯感覺得到。原因：「185.19」顯示 6 個字元，念出來卻是「一百八十五點一九」8 個音節，數字越多越快。

目前做法：
1. 用 **TTS 實際念的講稿**（國字）估每個子句長度。
2. ffmpeg `silencedetect`（-38 dB、≥0.12 s）找出音檔裡的停頓。
3. 用 DP 把每個逗號、句號切出的子句邊界對到停頓：字幕在停頓結束、開口那一刻才出現。範例 22 段的邊界全部都對到了停頓。
4. 子句再併成字幕條（8–24 字）。

沒有逐字時間戳（Whisper 模型要從 Hugging Face 下載，常被網路擋）。如果使用者回報某條不準，請他給時間點，看該段的 silencedetect 結果調整。

## 5. 成片與檔案大小

- 預設**不燒字幕**，.srt 另外上傳 YouTube（字幕 → 上傳檔案 → 含時間碼，語言選中文（台灣））。要燒字幕就 `make_final.py --burn`。
- 輸出 1080p30、CRF 28、`-tune stillimage`：黑板片 6 分鐘約 18 MB。原本 1080p60 CRF 20 是 41 MB，超過回寫使用者電腦的 20 MB 上限和聊天附件的 30 MB 上限；壓縮後公式和字幕仍清楚。
- **成片不再二次壓縮**：超過 20 MB 就改用聊天附件交付（見 SKILL.md 步驟 5），不要重新編碼降畫質。
- 封面用 `thumb.py`（1280×720，約 0.6 MB，低於 YouTube 的 2 MB 上限）。左半大字（≤ 2 行、每行 ≤ 6 字）、右半放這題最有辨識度的圖。

## 6. 環境與網路

- 渲染在 Linux 做（雲端沙箱或 WSL），執行 `bash scripts/setup_render_env.sh`。Manim 依賴的 `srt` 套件在某些 Ubuntu 上 build 失敗，腳本已內建繞法。
- 使用者電腦的 Cowork 本機 VM、以及雲端沙箱，通常都連不到 generativelanguage.googleapis.com。**配音一律在使用者的 Windows 跑**（run_tts.bat）。跑完後把 `audio/*.wav` 和 `durations.json` 搬回渲染環境。
- `.env` 放金鑰，**不要**打包、分享或 commit；只分享 env.example。
- 大檔（mp4、音檔）在雲端和使用者電腦之間搬動很慢，只搬必要的檔案。
