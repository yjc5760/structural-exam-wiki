# exam-errata — 題意與解析勘誤、重新驗算（五科通用）

修正**已存在**的正本，並讓所有下游跟著一致。每題有兩份正本（同資料夾 `XX/raw/solutions/XX-YYYY-N/`）：

| 正本 | 管什麼 | 錯了叫什麼 |
|------|-------|-----------|
| `XX-YYYY-N-problem.md` | 題意：考卷原文、公式／附表、判讀清單（使用者確認後凍結） | **題意勘誤**：下游所有依此題意寫成的解析、講義都要重驗 |
| `XX-YYYY-N.md` | 解析：計算與討論 | **解析勘誤** |

`XX` 是科目代碼（SS／RC／SA／SD／SM），所有路徑都在 `XX/` 底下。

> 授權依據：該科 `CLAUDE.md` 規則 1 的例外（解析勘誤四條件；SS 另有題目正本條款）。本 skill 是執行那些條件的標準流程。
> 規則 2 的界線：題目若仍是 `verified`，只有在**使用者明說要勘誤**時才能重算。

## 為什麼要這麼嚴

SS 在 2026-08-22 抽查 7 題，就有 3 題錯誤足以改變答案（43%）：把考卷原文「靠桿」讀成「鉸接」（挫屈載重高估 3 倍）、圖面銲接符號誤判、尺寸線量錯基準。
2026-11-02 題目正本試做又查出：解析重述漏抄題給 $L_p$、$L_r$、$C_b$ 而自行重算、把「標稱」強度答成設計強度（SS-2025-3）。
錯誤幾乎都出在**判讀與題意**而不是算術——所以第一步永遠是回考卷看圖，並先確定題意。

## 流程（每題）

### 1. 確認範圍
- 題號、科目、使用者指出的疑點（沒有特定疑點就做全面重驗）。
- 讀題目正本 `-problem.md`（有的話，看判讀狀態）、解析正本 `.md`、`question_index.json` 該題條目、`XX/SUBJECT.md` §8。
- 查 `wiki/queries/audit-ledger-XX.json` 有無此題：有的話讀它指向的盲解比對報告與盲解紀錄，`human` 欄是使用者已做的判定，
  勘誤以該判定為準（盲解紀錄是參考，不是證據；仍要走步驟 2–3）。

### 2. 回考卷原文判讀，先定題意（條件 ①）
- 用 PyMuPDF 把考卷該題所在頁、**以及參考公式頁**轉成圖：全頁約 150–300 dpi；支承符號、鉸接圓圈、尺寸線端點、銲接符號、隱藏線用 400–500 dpi。
- ⚠️ 不可只靠 `pdftotext`：CID 字型抽不到中文，poppler 缺語言包時轉圖也缺字；公式表、附表常是影像。
- 逐項核對並記下證據（頁碼、位置、dpi）：
  - 題意用字（「靠桿」「有側撐」「均佈的雙向彎矩」「標稱／設計」這類中心語）
  - 支承條件、邊界在兩個平面是否不同
  - 尺寸線量到哪條線、幾何是否和解析一致
  - 考卷給的公式、附表與參數：題目給定的**數值參數**直接用，不可自行重算；考卷印出的**規範公式、係數、$\phi$、載重組合**改用現行台灣規範（見步驟 4），§5 註明差異
- **與題目正本比對**：
  - 題目正本**已確認且與考卷一致** → 題意已定，直接進步驟 3。
  - 題目正本**與考卷不符** → 先做**題意勘誤**：修正 `-problem.md` 的 §1／§2／§4，頭表判讀狀態改「待確認（題意勘誤，日期）」，
    把差異交給使用者確認後再改回已確認；`problemStatus` 同步。題意一改，該題解析與引用它的講義、單元資料都要重驗。
  - **尚無題目正本** → 依 exam-solve「題目正本格式」把本步驟的判讀寫成 `-problem.md`（待確認），隨勘誤結果一起請使用者確認。

### 3. 數值獨立重算（條件 ②）
- 寫一支 Python 腳本，把解析裡**每一個數值**從題目正本的給定量重算一次；放在工作目錄，不放進 `raw/`。
- 每個數值做量綱檢查；關鍵結果用第二條路徑交叉驗算（不同公式、邊界代入、簡化極限、數值掃描對閉合解、平衡法對機構法）。
- 腳本最後印出 `MISMATCHES: n`，列出所有與正本不符的值。**n = 0 才算驗完**；不為 0 就逐項判定是正本錯還是腳本錯。

### 4. 規範層次（需要時）
- **規範版本一律用現行最新版台灣規範**（根目錄 `CLAUDE.md`「規範版本」，2026-11-14 起；各科版本見 `XX/SUBJECT.md` §7），不依考卷年份；
  題目指定舊版台灣規範時仍用現行版，§5 註明差異。唯一例外：題目明確指定 ACI（RC）或 AISC（SS）時，依題目指定規範。
- 照題目用：幾何尺寸、材料強度、載重大小與作用位置、鋼筋規格與面積、斷面性質表，以及題目直接給的數值參數（如 $L_p$、$L_r$、$C_b$、有效預力）；改用現行台灣規範：題目印出的規範公式、係數、強度折減因數 $\phi$、載重組合與載重因數、容許值、規範表格與限制值（考卷印在題目或提示裡也一樣）。
- 勘誤到的舊解若是依考卷年份規範寫的，一併改依現行台灣規範：舊 `## 6. 依最新規範對照` 的結果升為主線，原答案降為 §5 對照，頁尾修正日期寫明「改依現行台灣規範（<規範與版本>）」。
- 對條文有疑義時回查規範原文，不憑二手資料。

### 5. 修改解析正本
- 只改有錯的地方，保留原結構與 §3.5 VHA 格式（`CLAUDE-SPEC.md` §3.4）。
- §1 若仍是全文重述，順手改為「指向題目正本＋常見誤讀＋本解記號」（見 exam-solve 解析輸出格式），把這次的錯誤寫進常見誤讀。
- 頁尾加：`*修正日期：YYYY-MM-DD（修正內容；驗證方式）*`
- **清殘留**：改完後在正本內搜尋每個被改掉的舊值與舊觀念用語，§1 常見誤讀以外（§3 各步驟、§3.5 L1–L3、§4、§5 彙整、圖說）
  不得再出現。盲解比對已多次抓到「結論改了、前面步驟還是舊的」（SS-2009-1、SS-2018-3）。

### 6. 同步全部下游（條件 ③）
依序檢查並更新，**有引用到被改數值或題意的地方都要改**：

1. 本題圖解：有 `gen_XX-YYYY-N.py` 就更新腳本頂端的常數、用 struct-diagram 的 `render.py` 重跑並目視檢查；
   本次錯誤屬**判讀錯**（支承、幾何、尺寸線）且該題沒有圖時，建議補一張能攔下這個錯的圖（交給 `struct-diagram`）。
2. `study/problems-view/XX-YYYY-N.html`（用該科渲染腳本重生，題目正本會一起渲染）
3. `question_index.json`：`verificationStatus` → `unverified`；`tags` 只增不刪（append-only）；題意勘誤時同步 `problemStatus`
4. `study/data/unit-*.json`（該題摘要、公式用途標籤）→ 重跑 `build_unit_page.py <單元>` 並重出單元總覽 PDF
5. `study/lecture-*.html`、`study/textbook-*.html` 中引用此題數值或結論的段落（改了就重出 PDF）
6. 全庫 grep 被改的關鍵數值或錯誤觀念，其他題目有同樣錯誤的一併列出（不要順手改別題正本，列出來另開勘誤）
7. 儀表板資料（該科有重建腳本時執行）

（wiki 各層已於 2026-11 封存，不再同步 `wiki/problems/`。）

### 7. 記錄（條件 ④）
在該科 `wiki/queries/log.md` 依該檔慣例 append 一筆，三件事都要寫：

```
- YYYY-MM-DD｜FIX-XX-…｜題號：
  改了什麼（原答 → 新答含單位；題意勘誤或解析勘誤；改動章節）
  為什麼錯（錯誤類型：題意／判讀／觀念／算術／規範版本／遺漏檢核；證據：考卷第 n 頁何處、dpi）
  怎麼驗證（腳本重算 n 個數值 MISMATCHES: 0；交叉驗算方式）
  同步的下游（逐項列出）
```

影響答案的批次勘誤，另在 `XX/SUBJECT.md` §9 CHANGELOG 加一列（影響多科或根目錄者改記根目錄 `CHANGELOG.md`）。

**回寫 audit ledger**：`wiki/queries/audit-ledger-XX.json` 已有此題時，只改兩欄：
- `fixed` 設為今天日期（`pending.py --recheck` 會據此把它排進落實檢查）
- `human` 若還是空的，而使用者在本次對話明說了判定（「盲解對」「採 XX 解讀」），照原話填入；沒明說就留空

其他欄位不動；ledger 沒有此題時不新增條目。

### 8. 回報使用者

| 題號 | 錯誤類型 | 原答 → 新答 | 證據 | 驗證 |
|------|---------|------------|------|------|

並提醒：該題已退回 `unverified`，請人工複核後說「將 XX-YYYY-N 的 verificationStatus 改為 verified」；
題意勘誤者另請確認題目正本。勘誤來自盲解比對者，提醒可用 exam-wiki-audit 的 `pending.py --recheck` 做落實檢查。
列出所有動到的檔案路徑，git commit 由使用者自己做。

## 批次勘誤（某單元或多題）

- 依子項分批，同一批用同一套重算腳本框架，最後合併報告。
- 每題仍逐一完成步驟 2–7；不要先改完全部再一起同步。
- 批次開始前可先跑分診（見下節），把可疑題排在前面；該單元還沒有題目正本時，建議先用 exam-solve 補題目正本再勘誤。

## 分診：xcheck

```
python scripts/xcheck.py XX -o XX/wiki/queries/xcheck-XX-YYYY-MM-DD.md
```

找出係數不一致、單位制混用、條件式規定寫成絕對規則等可疑處。它只是**分診清單**（實測真陽性率約 1/6），每一筆都要回到步驟 2–3 確認，不可直接據此改正本。

## 不要做的事

- 不看考卷圖就改；只憑記憶或單一參考書改數值
- 題意沒先定就改解析；或題目正本已確認卻在解析裡另寫一套題意
- 自行重算題目已給定的參數
- 只改下游、不改正本（下次重新渲染會被蓋回錯誤）
- 勘誤後保留 `verified`
- 改了正本卻沒清掉同檔其他章節的舊值（勘誤殘留）
- 刪除 log 舊紀錄或刪除舊 tags
