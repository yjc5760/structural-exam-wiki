## 2. 核心工作流程

```
【解析新考題】（exam-solve skill）
  對 Cowork 說：「解析 XXXX 年 SD 考卷」
    ↓ Cowork 建立題目資料夾、從考卷擷取附圖、寫題目正本 SD-YYYY-N-problem.md（考卷原文＋判讀清單）
  你檢查判讀清單（尤其標「不確定」的項目）
    ↓
  告知 Cowork：「判讀確認，請開始解題」
    ↓ Cowork 一次解一題，存 .md 檔（含 LaTeX 公式）
  你驗算後對 Cowork 說：「將 SD-XXXX-N 的 verificationStatus 改為 verified」

【為既有題目補題目正本】（exam-problem-split skill）
  對 Cowork 說：「SD 題目正本 第 n 批」

【新增方法】
  對 Cowork 說：「add method [方法名]」（只寫 raw/solutions/methods/）

【複習查詢】
  直接向 Cowork 提問，或開 index.html、study/ 講義、影片講義/
```

> **所有操作都對 Cowork 說即可，不需要終端機。**

## 3. Cowork 指令速查

完整說明見根目錄 [CLAUDE-CODE.md](../CLAUDE-CODE.md)。

### 3.1 解題與 raw 資料維護

| 觸發語句 | 功能 |
|---------|------|
| `解析 XXXX 年 SD 考卷` | 建立題目資料夾、擷取附圖、寫題目正本待確認（exam-solve） |
| `判讀確認，請開始解題` | 題目正本凍結，一次解一題 |
| `勘誤 SD-XXXX-N` | 回考卷重判、重算、同步下游（exam-errata） |
| `繼續下一題` | 觸發解析同一份考卷的下一題 |
| `將 SD-XXXX-N 的 verificationStatus 改為 verified` | 人工驗算通過後標記 |
| `將 SD-XXXX-N 的 verificationStatus 改為 needs-review` | 發現錯誤時標記 |

### 3.2 知識庫維護（ingest／compile／lint／add concept 已隨 2026-11-01 wiki 封存停用）

| 觸發語句 | 功能 |
|---------|------|
| `status SD` | 驗證進度統計 |
| `reindex` | 修正 hasSolution 不一致 |
| `add method [名稱]` | 新增解題方法論（raw/solutions/methods/） |
| `更新儀表板資料` | ⚠️ SD 目前暫用原 repo 儀表板：用 `SD/scripts/refresh-dashboard.ps1`，不要跑共用的 `refresh_dashboard.py`（見 `SUBJECT.md` §10） |

### 3.3 備考分析類

| 觸發語句 | 功能 | 輸出 |
|---------|------|------|
| `frequency` | 統計各考點歷年出現次數 | 對話回覆；全科熱圖見 `study/frequency-SD.html` |
| `analyze YYYY` | 深度分析某一年考卷的考點分布 | 對話回覆 |
| `predict` | 根據歷年頻率推測最可能出現的考點 | 對話回覆 |
| `study SD-UN-n` | 子項單元總覽（unit-overview skill）。⚠️ SD 尚未導入，現有的是舊式命題分析／給背頁，第一次做之前先看 `SUBJECT.md` §3、§10 | `study/unit-SD-UN-n.html` |

### 3.4 查詢快捷類

| 觸發語句 | 功能 |
|---------|------|
| `find [關鍵字]` | 搜尋含某關鍵字的題目 |
| `related SD-XXXX-N` | 找出與某題考點相似的其他題目 |
| `unverified` | 列出所有有解析但尚未驗算的題目 |
| 直接提問 | 自由查詢知識庫 |

## 4. 複習使用指南

### 4.1 依考年複習

開啟 `index.html` → 依年份篩選 → 點入題目瀏覽頁（`wiki/by-year.md` 已於 2026-11-01 封存）。

### 4.2 依子項複習

先開 `study/frequency-SD.html` 看哪些子項常考（主考點 U1-3 遙遙領先，其次 U2-2、U3-2），再依序讀該子項的 `study-SD-*`（考什麼）→ `lecture-SD-*` 或 `影片講義/`（為什麼）→ `formula-given-SD-*`（哪些公式考卷會給、哪些要背），最後從頁內題號連到題目瀏覽頁練習。

### 4.3 依題型複習（診斷決策樹）

> 診斷頁已於 2026-11-01 封存至 `archive/wiki/diagnosis/`（未逐頁核對，僅供參考）；建議優先讀 `study/` 講義，題型關鍵字見 `SUBJECT.md` §6。

| 題型 | 封存的診斷頁 |
|------|--------|
| 單自由度系統 | `archive/wiki/diagnosis/sdof.md` |
| 多自由度系統 | `archive/wiki/diagnosis/mdof.md` |
| 反應譜分析 | `archive/wiki/diagnosis/spectrum.md` |
| 規範設計 | `archive/wiki/diagnosis/code-design.md` |

### 4.4 查詢規範條文

封存的 `archive/wiki/code-ref/` 只做到「主題 ↔ 規範」對照，沒有條文號；引用條文號前須對照正式規範原文，並注意考卷年份適用的規範版本。

### 4.5 直接問 Cowork

```
模態參與因子和有效模態質量的關係？
SRSS 和 CQC 什麼時候結果差很多？
SD-2018-3 的考點是什麼？
哪幾題考過隔震等效線性化？
Rayleigh 法的形函數怎麼選？
```

## 5. 常見問題

**Q：解析 .md 放在哪裡？**
- 原始來源（唯讀，例外見根目錄規則 1）：`raw/solutions/SD-XXXX-N/SD-XXXX-N.md`
- 題目瀏覽頁：`study/problems-view/SD-XXXX-N.html`（舊 `wiki/problems/` 已封存）

**Q：如何更正答案？**
對 Cowork 說「勘誤 SD-XXXX-N」→ 回考卷重判、重算、改正本、同步下游，`verificationStatus` 退回 `unverified`，在 `wiki/queries/log.md` 記錄；你複核後再改回 verified。

**Q：`designMethod`、`analysisMethod` 該填什麼？**
兩欄都要填。`designMethod` 是題型四值：動力分析／規範計算／概念題／混合，判準見 `SUBJECT.md` §3；`analysisMethod` 寫方法描述（例：`MDOF模態分析`、`反應譜分析（SRSS振態疊加）`），與解析標頭「分析方法」一致。

**Q：截圖要怎麼命名？**

| 類型碼 | 內容 | 範例 |
|--------|------|------|
| `fig` | 題目附圖（結構模型、地震紀錄） | `SD-2018-1-fig-1.png` |
| `chart` | 設計圖表（反應譜、遲滯迴圈） | `SD-2018-1-chart-1.png` |
| `eqn` | 公式截圖 | `SD-2018-1-eqn-1.png` |
| `hand` | 手寫補充 | `SD-2018-1-hand-1.png` |

**Q：目前解析進度？**
對 Cowork 說 `status SD` 即可取得最新統計。
